## Architecture Principles

### 1. Dependency Rule
Dependencies point **inward**:
- `infrastructure` depends on `domain`
- `usecase` depends on `domain`
- `domain` depends on nothing (pure business logic)

### 2. Repository Pattern
- **Interfaces** defined in `domain/repository/` (ports)
- **Implementations** in `infrastructure/database/` (adapters)
- Usecases depend on interfaces, not implementations

### 3. Feature-Based Organization
Usecases organized by feature (vertical slices):
- Each feature has its own directory
- Related DTOs stay with their feature
- Shared code goes in `common/`

## Migration Steps

### Step 1: Generate Database Code
```bash
# Install sqlc
sqlc generate

# This generates code in internal/infrastructure/database/postgres/
```

### Step 2: Implement Repository Adapters
Create implementations in `infrastructure/database/postgres/`:

```go
// session_repository.go
package postgres

import (
    "context"
    "github.com/yourusername/.../internal/domain/entity"
    "github.com/yourusername/.../internal/domain/repository"
)

type SessionRepositoryImpl struct {
    queries *Queries
}

func NewSessionRepository(db *DB) repository.SessionRepository {
    return &SessionRepositoryImpl{
        queries: New(db.Pool()),
    }
}

func (r *SessionRepositoryImpl) Create(ctx context.Context, session *entity.Session) error {
    _, err := r.queries.CreateSession(ctx, CreateSessionParams{
        SessionID: session.SessionID,
        UserID: session.UserID,
        // map all fields...
    })
    return err
}

// Implement other methods...
```

### Step 3: Move Usecases to Features
Move existing usecase files to appropriate feature directories:

1. `authentication.go` → `usecase/authentication/login.go`
2. `registration.go` → `usecase/registration/personal.go`
3. `registration_managed.go` → `usecase/registration/managed.go`
4. `password.go` → `usecase/password/reset.go`
5. `session.go` → `usecase/session/manager.go`

### Step 4: Update Imports
Update all imports to reflect new structure:

```go
// Old
import "internal/usecase"

// New
import (
    "internal/usecase/authentication"
    "internal/usecase/registration"
)
```

### Step 5: Update Dependency Injection (wire.go)
```go
// Old
type Dependencies struct {
    RegistrationUsecase *usecase.RegistrationUsecase
}

// New
type Dependencies struct {
    // Authentication
    LoginUsecase   *authentication.LoginUsecase
    LogoutUsecase  *authentication.LogoutUsecase
    
    // Registration
    PersonalRegistration *registration.PersonalUsecase
    ManagedRegistration  *registration.ManagedUsecase
    
    // Password
    PasswordResetUsecase  *password.ResetUsecase
    PasswordChangeUsecase *password.ChangeUsecase
    
    // Session
    SessionManagerUsecase *session.ManagerUsecase
}
```

## Benefits of New Structure

1. **Clear Separation of Concerns**
   - Domain logic is pure and testable
   - Infrastructure is pluggable
   - Easy to mock dependencies

2. **Feature-Based Organization**
   - Related code stays together
   - Easy to find and modify features
   - Better for large teams (less conflicts)

3. **Type-Safe Database Access**
   - sqlc generates type-safe queries
   - Compile-time query validation
   - No ORM overhead

4. **pgx Performance**
   - Native PostgreSQL protocol
   - Connection pooling
   - Better performance than database/sql

5. **Maintainability**
   - Standard Go project layout
   - Easy onboarding for new developers
   - Testable architecture

## 6. gRPC Service Implementation

### 6.1 File: `infrastructure/grpc/ProductSkuGrpcService.java`

**Path:** `product-service/src/main/java/com/platform/productservice/infrastructure/grpc/ProductSkuGrpcService.java`

- [x] Create `@GrpcService` class extending generated `ProductGrpcServiceGrpc.ProductGrpcServiceImplBase`
- [x] Inject: `ProductSkuReadService`, `CategoryServicePort`, `CategoryRepository`, `ProductRepository`, `GrpcProtoMapper`
- [x] Implement `GetProductSku`:
  - Step 1: `Redis GET product:sku:{skuId}` via `ProductSkuReadService`
  - Step 2: PER (Probabilistic Early Expiration): if TTL < 5%, query DB and overwrite cache
  - Step 3: Cache miss: acquire distributed lock, query DB, cache with TTL 3600s, release lock
  - Step 4: Return `ProductSkuResponse`
  - Step 5: On error, return `NOT_FOUND` or `INTERNAL` status
- [x] Implement `GetBatchProductSkus`:
  - Step 1: `Redis MGET` all keys in single round-trip via `ProductSkuReadService`
  - Step 2: Identify `missedSkus` (cache misses)
  - Step 3: If `missedSkus` not empty: batch query DB, warm cache
  - Step 4: Build response from cache + DB results
  - Step 5: Return `BatchProductSkuResponse`
- [x] Implement `GetCategoryTree`:
  - Call `CategoryService.findTree()`
  - Build full category tree with children recursively
  - Map to protobuf response
- [x] Implement `GetProductSnapshot`:
  - Query product by ID
  - Include SKUs and media if requested
  - Map to protobuf response
- [x] Interceptors applied via `@GrpcGlobalInterceptor` annotations
- [x] Error handling returns correct gRPC Status codes

# ADR-015: Detect drift between the generated Product stubs and the canonical proto

## Context

Cart keeps generated Go stubs of the Product gRPC contract in `internal/infrastructure/product/pb`. The Java
services check their proto copies byte for byte (`ProtoCopyDriftTest`, `ProtoCopyTest`); Cart had `make generate`
and `make check-lua` for the Lua scripts but nothing that said the stubs were current. They were not:
`product_service.pb.go` was missing `base_price`, `catalog_revision` and `category_ids` (fields 10 to 12 of
`Sku`), because the proto had been extended and the stubs never regenerated. Cart ignores those fields, so nothing
broke, but a field that Cart later needs would have read as empty with no error.

## Decision

1. Regenerate the stubs from the canonical proto with the versions they were generated with (protoc 24.4,
   protoc-gen-go 1.33.0, protoc-gen-go-grpc 1.3.0). `scripts/generate-pb.sh` does it in the same golang container
   as the other scripts, so the machine needs neither protoc nor Go. Only `product_service.pb.go` changed; the
   gRPC stub and `money.pb.go` regenerated byte for byte.
2. `make generate` now also records the SHA-256 of each source proto (line endings normalized) in
   `pb/PROTO_SHA256`.
3. `TestGeneratedStubsMatchCanonicalProto` compares those hashes with the files in `contracts/` and fails with the
   command to run. It skips when `contracts/` is not next to the service, as in a Docker build whose context is
   only the service directory. `make check-pb` runs the same comparison without Go.
4. The rule stays "edit the proto in `contracts/`, then regenerate"; the stubs are never edited by hand.

## Consequences

Changing `product_service.proto` now fails Cart's unit tests until the stubs are regenerated and the hash file
committed. The recorded hash proves the stubs were generated from that content, not that they compile against it;
the build does that.

## Verification

The test passes on the regenerated stubs and fails when the first hash is altered (checked by hand). The full Cart
suite and `go vet` stay green.

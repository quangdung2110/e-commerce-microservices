# P1 caller spoofing — local mesh deployment and verification

Date: 2026-11-04 (Asia/Bangkok).

The original finding is reproducible at the application-filter boundary: a caller can supply an allowlisted
`X-Service-Identity` without proving that identity. This deployment establishes the missing authentication
and authorization boundary on the **isolated local kind cluster**, not on production or Docker Compose.

## Deployment

- Cluster/context: `kind-ecommerce-mesh`; dedicated kubeconfig `.tools/mesh/kubeconfig`. The user's default
  context remains `docker-desktop`.
- Kubernetes 1.35.8, two kind nodes, node image pinned by digest.
- Istio ambient 1.31.3 installed with official Helm charts from the checksum-pinned release archive.
  Pilot, CNI, ztunnel, and waypoint proxy images are digest-pinned. Two waypoint replicas are ready.
- All 13 deployed business service Deployments are Ready, alongside Frontend, Traefik, gateway-auth,
  local email-provider simulators, and the local data services. Existing local application images are used;
  Payment was rebuilt from source during verification. Exact image IDs are in `pods.json`.

## Changes that close P1

1. Keep separate ServiceAccounts, do not mount application Kubernetes tokens, and verify that callers
   cannot deploy workloads, patch Deployments, or create ServiceAccount tokens.
2. Require STRICT mTLS on business listeners; certificates establish the caller principal independently
   of headers. Public entrypoint exceptions are only Traefik 80/443 and Frontend 3000.
3. Enforce principal + listener port + HTTP method/path or gRPC operation at the waypoint. URI templates
   preserve path-segment boundaries instead of broad suffix matches. Internal/public listeners cannot
   inherit each other's grants.
4. Permit only the waypoint principal at the business Pod's L4 boundary. Enable waypoint handling of
   both Service and workload traffic. Direct Pod IP requests fail closed, including otherwise authorized
   callers; application clients use Service DNS.
5. Remove the unrestricted Prometheus L4 exception. Only exact GET metrics endpoints on HTTP ports are
   allowed through the waypoint. Add exact caller/path/method grants for existing health checks.
6. Preserve namespace enrollment labels during application updates. Keep local provider exceptions
   restricted to Notification, a particular destination selector, and its SMTP/AWS API port.
7. Preserve the application attribution-header allowlists as a second check. They do not prove identity.

Policy changes originate in `docs/mesh/runtime-contract.md` and `deploy/mesh/topology.yaml`, then are
generated into `deploy/mesh/generated/`. Kubernetes Service ports now declare `appProtocol`; workloads
and ServiceAccounts disable token automounting. `local.py` installs/applies only the dedicated kind context.

## Runtime tests

Runner: `py deploy/mesh/verify_live.py --reuse-probes`.

**54/54 checks passed**, using real Inventory, Payment, Product, Cart and User application endpoints.
Caller test Pods use actual workload ServiceAccounts; the forged header value is supplied independently.
Checkout test traffic crosses from the control-plane node to the worker hosting the applications.

| Scenario | Observed result |
|---|---|
| Checkout previews Inventory | 200 |
| Checkout claims Order and reads Inventory reservations | 403, `RBAC: access denied` |
| Order reads an absent Inventory reservation / Payment transaction | Domain 404, demonstrating authorized application access |
| Checkout claims Order and queries Payment | 403 from mesh |
| Order claims Finance Ops | 403 from mesh |
| Finance Ops queries an absent financial journal | 404 `FINANCIAL_JOURNAL_NOT_FOUND` |
| Authorized Order omits attribution header | Application 401; existing filter remains effective |
| Checkout reads Cart snapshot / User address snapshot | 200 empty cart / domain 404 |
| Order claims Checkout against Cart or User | 403 from mesh |
| Checkout calls User's internal path on the public listener | 403 from mesh |
| Checkout supplies forged user ADMIN headers to Inventory admin API | 403 from mesh |
| HTTP requests directly to business Pod IP | 403, including Order; no Service-policy bypass |
| Unenrolled Pod in the allowed ecommerce namespace sends a forged header directly to a Pod | Connection reset; plaintext rejected |
| Prometheus identity reads metrics | 200 |
| Prometheus identity calls business routes, including Pod IP, with forged Order header | 403 |
| Prometheus identity POSTs the metrics endpoint | 403 |
| Checkout calls Product GetSku via Service DNS | gRPC OK, absent-SKU response |
| Order sends Checkout metadata to the same RPC | gRPC PERMISSION_DENIED |
| gRPC directly to Product Pod IP | PERMISSION_DENIED |
| Caller identities attempt Deployment changes, Pod creation, token creation | Kubernetes RBAC denies |
| Existing gateway/startup health checks | 200 for the correct caller; 403 for the wrong caller |
| Frontend / gateway requiring user auth | 200 HTML / 401 without bearer token |

No payment, refund, reservation, or financial correction is created. Domain 404s intentionally use
well-formed technical identifiers absent from the fresh local database. Invalid arguments and 503s
are not counted as successful positive authorization tests.

## Limits and independent observation

- **Production and Docker Compose are unchanged runtimes.** Do not set production transport readiness
  to true based on this local result. Docker Compose continues to have no mesh.
- The full observability stack is not installed here. Applications attempt to export traces to an absent
  collector; tracing and related analyzer warnings remain outside this security verification.
- Default kind networking does not enforce Kubernetes NetworkPolicy. P1 tests deliberately use a plaintext
  caller in the otherwise allowed namespace, so rejection demonstrates the mesh boundary, not NetworkPolicy.
- Certificate validity/identity are checked now; full-lifetime rotation, CA failure scenarios, failover under
  load, retry behavior, and a complete purchase/refund flow have not been certified.
- `GET /internal/v1/payment/review-cases` returns application 503 `DEPENDENCY_UNAVAILABLE` for the authorized
  Finance Ops caller. The mesh admits that caller; forged Order remains denied. This independent application
  issue was observed before and after rebuilding Payment and is preserved in `application_diagnostics`.
  It is **not counted as a passing positive read**; the positive Finance test uses the working journal lookup.
